# Ravel Control Center – مركز تحكم رافل

منصة موحّدة لإدارة **رافل للتخزين (Ravel Storage – أبوظبي)**. تجمع **Zoho Creator** (الوحدات والخارطة) و **Zoho Books** (الفواتير والتحصيل) في لوحة واحدة.

## المرحلة 1 – ما تم بناؤه

| الصفحة | الميزات |
|---|---|
| **لوحة التحكم** `/` | الإشغال، الدخل الشهري المتكرر، المستحقات، المتأخرات، الدخل الضائع يومياً، المفوتر مقابل المحصّل (6 أشهر)، الإشغال حسب الحجم مع اقتراح رفع السعر، أعمار الديون، أعلى المتأخرين، العقود التي تنتهي قريباً |
| **الخارطة الحيّة** `/map` | مخطط علوي للوحدات والمساحات المفتوحة (فلترة بالفرع والطابق: أرضي / ميزانين) ملوّن حسب الحالة (متاحة / مؤجّرة / محجوزة / عقد ينتهي / متأخرة / صيانة)، بحث وفلترة بالمنطقة والحالة، تحديث تلقائي كل دقيقة. عند الضغط على وحدة: **حجز، تمديد، إصدار فاتورة، إخلاء، صيانة، تعديل السعر، تذكير واتساب** |
| **الفواتير** `/invoices` | كل فواتير Books مع فلترة (غير مسددة / متأخرة / مدفوعة) وبحث، ورابط كل فاتورة لوحدتها على الخارطة |
| **الربط والإعدادات** `/settings` | فحص الاتصال، معالج توليد Refresh Token **مع اكتشاف منطقة الحساب تلقائياً**، واكتشاف تطبيقات Creator وتقاريرها وحقولها |

بدون مفاتيح Zoho تعمل المنصة ببيانات **تجريبية**، وبمجرد إضافة المفاتيح تتحول للبيانات الحقيقية.

## كيف يعمل الربط

- **Creator**: نقرأ تقرير الوحدات ونحدّث السجل عند الحجز أو التمديد أو الإخلاء (`PATCH`).
- **Books**: نقرأ الفواتير ونربطها بالوحدة عن طريق حقل `reference_number`، وهو رقم الوحدة. عند إصدار فاتورة نبحث عن العميل وننشئه إذا لم يكن موجوداً.
- **المنطقة**: إذا لم يُحدد `ZOHO_DC` تجرّب المنصة كل مناطق Zoho وتستخدم `api_domain` الذي يرجعه Zoho.
- كاش لمدة 60 ثانية لتجنّب حدود الطلبات، ويُمسح فوراً بعد أي تعديل.

## النشر على Vercel (مجاني)

1. في Vercel: **Add New ← Project** واختر هذا المستودع، ثم اجعل **Root Directory** = `platform`.
2. أضف `ADMIN_PASSWORD` في **Environment Variables** ثم انشر. ستعمل المنصة ببيانات تجريبية.
3. ادخل على `/settings` واتبع الخطوات 1 و 2، ثم أضف المتغيرات الناتجة (`ZOHO_CLIENT_ID`، `ZOHO_CLIENT_SECRET`، `ZOHO_REFRESH_TOKEN`، `ZOHO_DC`) وأعد النشر.
4. من الخطوة 3 في الإعدادات حدّد `ZOHO_CREATOR_OWNER` و `ZOHO_CREATOR_APP` و `ZOHO_CREATOR_UNITS_REPORT`.
5. طابق أسماء الحقول في `src/config/mapping.ts`، أو عن طريق `ZOHO_CREATOR_FIELD_MAP`.

كل المتغيرات موضّحة في `.env.example`.

> ⚠️ لا تضع المفاتيح في الكود ولا ترسلها في المحادثات. مكانها متغيرات البيئة فقط.

## التشغيل محلياً

```bash
cd platform
npm install
cp .env.example .env.local   # اختياري
npm run dev                   # http://localhost:3000
```
في وضع التطوير لا تُطلب كلمة مرور إلا إذا ضُبط `ADMIN_PASSWORD`. في الإنتاج كلمة المرور **إلزامية**.

## هيكل المشروع

```
src/
  config/mapping.ts     ← ربط حقول Creator + الأحجام والأسعار الافتراضية
  lib/zoho/             ← المصادقة (اكتشاف المنطقة) + Creator + Books
  lib/data/             ← مصدر البيانات: mock أو zoho بنفس الواجهة
  lib/actions.ts        ← منطق الحجز/التمديد/الإخلاء/الفوترة
  lib/kpis.ts           ← حساب المؤشرات
  lib/layout.ts         ← رسم الخارطة (من إحداثيات Creator أو ترتيب تلقائي)
  app/(app)/            ← الصفحات
  app/api/              ← واجهات API (محمية بكلمة المرور)
```

## المراحل القادمة
- **2 – العمليات:** تذكيرات تحصيل تلقائية (واتساب/SMS)، إقفال الوحدة عند التأخر، سجل نشاط.
- **3 – العميل:** بوابة العميل (دخول بـ OTP، فواتيره، دفع أونلاين)، حجز ذاتي من الموقع، عقود إلكترونية.
- **4 – الذكاء:** تسعير ديناميكي، مساعد ذكي بالعربي، تقارير أسبوعية تلقائية.
